# hawkbell compared with other projects

This page sets hawkbell next to the open-source projects closest to it (uber/ADR, perplexityai/numbat, Agent Beacon, Agentmetry, snyk/agent-scan, agent-bom and the AI tables built into Fleet's agent) and, briefly, next to the commercial products in the same space. It is meant to help someone choose, so it says plainly where the others are ahead.

The state described is **as of 2026-11-12**. The other projects move quickly (agent-bom published 181 releases in under nine months [BOM-1]); check the cited sources before relying on a cell.

## How to read this page

- **Cells about other projects** carry a source key such as `[NB-1]`. Every key is resolved in [Sources](#sources) to two things: the section of the research report written for this project (the reports are design notes kept outside the repository, dated 2026-11-11) and the primary source that report itself cites (a file at a commit or a URL, with line numbers where the report gives them). For the open-source projects the research read the code and documentation. **The commercial products were researched from search-engine summaries only**: their sites were not reachable from the research environment, so everything said about them is a vendor claim, not something read or tested [PV-1].
- **Cells about hawkbell** are marked **verified** (shown by a recorded run against real software; the key `E1`...`E9` links the record) or *unverified* (implemented and covered by unit tests, or a design property, but not shown end to end). The evidence files are listed under [Evidence for hawkbell](#evidence-for-hawkbell).
- "Not found" means the research report looked and did not find it; it is not proof of absence.

## What the other projects do better

- **numbat and Agent Beacon cover far more agents.** numbat's matrix has 28 agents with exact artifact, hook and managed-policy paths, and its `scan`/`timeline` forensics work on a machine that was never instrumented [NB-1]. Agent Beacon covers 29 runtimes, adds a browser extension for chat web apps, a CI wrapper and cloud-sandbox hooks [AB-1]. hawkbell collects activity from 5 agents (hooks) and 4 (transcripts), and has run against one real agent. If breadth of agents matters most, start with them; hawkbell can read numbat's records (below).
- **numbat's hook does detection where hawkbell's usually does not.** numbat evaluates CEL and sequence rules in the hook, keeping a bounded window of session state between hook calls, with no daemon [NB-1] [NB-3]. hawkbell's default hook only records and leaves detection to the root daemon; evaluating rules in the hook is an option for daemonless use and costs more per event (E8).
- **uber/ADR has an LLM triage tier and real production data.** Its two-tier detector reasons about tool semantics, which hawkbell's deterministic rules cannot do; ADR also published a peer-reviewed account with production alert labels at Uber's scale (7,200 hosts in the paper, 30,000 endpoints in the slides) [ADR-T1] [ADR-P1] [ADR-P2]. hawkbell has no production deployment and no LLM tier; findings that would need a judge are only tagged `escalate`.
- **Fleet's tables need no extra binary.** On a host with fleetd 1.59.0 or later, `ai_tools` inventories every home's agents, MCP servers, plugins and extensions with risk flags, and Fleet tunes it to run hourly [FL-1] [FL-2]. Inventory alone is no longer a reason to install anything on a Fleet host; hawkbell's Fleet content uses `ai_tools` in its `fleetd` profile and its tier 1 needs no hawkbell binary at all (`deploy/fleet/README.md`).
- **Agentmetry sees MCP tool lists and ships more SIEM mappings.** Its stdio MCP proxy fingerprints `tools/list` and flags a changed tool list (a rug pull); hawkbell never starts or proxies an MCP server, so it hashes the declaration, not the tool list. Agentmetry also ships a Sigma pack, ECS, HEC, UDM and Sentinel mappings and a hash-chained trail [AM-1].
- **snyk/agent-scan analyses tool descriptions and skill contents** (prompt injection in tool descriptions, malicious code in skills) in Snyk's service, and signs its releases [SN-2] [SN-5]. hawkbell does not scan tool descriptions and its binaries are unsigned.
- **agent-bom covers vulnerability management.** CVE blast radius across agents, MCP servers and packages, SBOM formats (CycloneDX, SPDX), SARIF, a UI and an MCP gateway with policy [BOM-3] [BOM-4] [BOM-5] [BOM-6]. hawkbell has none of these.
- **Signed packages.** Agent Beacon and snyk/agent-scan ship signed artefacts [AB-1] [SN-5]; hawkbell does not yet (E9).

## What hawkbell adds

Among **open-source** projects, as of 2026-11-12, the research did not find the following elsewhere. Pieces of each exist, and they are named:

1. **Sensor health, per-agent hook coverage and findings as osquery tables, with Fleet GitOps content whose policies fail closed.** **Verified** (E2). Closest elsewhere: Agentmetry's heartbeat with `degraded` and `hooks_silent`, delivered to a SIEM rather than to osquery [AM-1]; Fleet's own `ai_tools` inventory, which has no detections or health [FL-1]; numbat ships no osquery content [NB-1].
2. **A Fluent Bit contract tested by killing Fluent Bit with its output down**, plus head-of-line and rejected-chunk tests against the real image. **Verified** (E3). Uber ships through Fluent Bit internally but released no configuration [ADR-P1].
3. **Corroboration of the agent's self-reported surfaces by a root-observed one.** The hook-bypass finding requires the process monitor; hook and transcript records are stamped user integrity. *Unverified* end to end (unit tests). EDR vendors claim OS correlation in their commercial products [PV-4].
4. **Per-rule false-positive rates from replaying real agent sessions**, next to an incident-derived scenario corpus with benign look-alikes and mutation-based robustness. Measured (E5, E6), with the limits stated there: one workload, synthetic attacks by the rules' author. Agentmetry ships a 57-case benchmark with 31 benign cases [AM-1], ADR-Bench has 261 benign tasks [ADR-T2], and the ADR paper reports analyst labels of production alerts [ADR-P2]; per-rule rates over replayed real sessions were not found elsewhere.
5. **A Kubernetes node sensor for agents in containers.** Partly verified with Docker, not on a cluster (E4). agent-bom has Kubernetes content (a Helm chart, `kubectl` and CRD discovery and a passive DaemonSet) [BOM-5] [BOM-6]; none of the other open-source projects reads agents in other containers from the node [OSS-1] [ADR-D1] [SN-5].

## Commercial products, as a category

Search summaries describe products from CrowdStrike (Falcon Guardian / Falcon AIDR), Microsoft Defender for Endpoint, Palo Alto Networks (Koi), Pillar, Noma, Zenity, Backslash, QuilrAI, Pluto, Jamf, Knostic and BeyondTrust, among others [PV-2]. By those summaries they are built from configuration discovery, the agents' own hooks, often an MCP proxy, and, for the EDR vendors, their existing kernel sensor [PV-2]. The one vendor mechanism read first-hand, Endor Labs' public MDM scripts, is the same hook mechanism hawkbell uses, with the hook binary in the user's home directory and API credentials in each laptop's configuration [PV-3].

What the category reportedly has that hawkbell does not: kernel-level process, file and network ground truth from an EDR sensor, curated reputation intelligence for MCP servers and skills, TLS inspection, LLM-based intent classification and managed response [PV-4]. What none was found to publish: an event schema, detection rules, a benchmark, or coverage of containers and CI runners [PV-2]. Treat both lists as claims from public material that was not opened or tested [PV-1].

## Running hawkbell next to the others

- **numbat**: `hawkbell detect --format numbat` evaluates numbat's NDJSON with hawkbell's rules, the daemon follows numbat files through `sources.adapters`, and `deploy/fluent-bit/numbat.yaml` routes them; the adapter is experimental and was built from numbat's documentation, not run against a numbat binary (`internal/adapter`). The Fluent Bit routing **verified** (E3).
- **Hooks of other sensors**: `hawkbell hooks install` recognises numbat's, Agent Beacon's and Snyk Agent Guard's handlers and writes nothing next to them unless `--coexist` is given, because two handlers double the cost of every tool call (`internal/hookinstall`; the Agent Beacon command line is *unverified*).
- **Fleet's `ai_tools`**: the generated `fleetd` profile uses its rows and risk flags beside hawkbell's tables (`deploy/fleet/README.md`).
- **uber/ADR**: hawkbell's skill folder hash is byte-compatible with ADR Discovery's, so skill indicators can be shared (`internal/discovery`; see NOTICE).
