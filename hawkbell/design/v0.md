# Design v0 (strawman to be attacked) — working name "spoor"

Status: baseline proposal written by the lead before red-teaming. Every numbered assumption (A1..A34) is a claim the design depends on. Red-teamers: break them with evidence.

## 1. Thesis

Incumbents split into three camps, none of which gives a security team a real-time, fleet-scale, vendor-neutral signal about what agents DO:
- Inventory scanners (snyk/agent-scan, agent-bom, Golf, agentshield, Fleet's own `ai_tools` table in fleetd >= 1.59): what is installed/configured. One-shot or scheduled, mostly Python, several upload to a vendor cloud.
- uber/ADR: hourly batch scrape of at-rest transcripts (whole-session blobs, no redaction, no hooks, no tamper signal), LLM-based detection run server-side in batch ($0.024 and 18.5 s per session on bench; production alerts 34% TP / 49% FP; paper concedes detections land after credentials were already exposed). Prevention and Explorer are withheld.
- Commercial (CrowdStrike AIDR, Pillar, Prisma AIRS/Koi, Noma, Zenity): closed, vendor cloud, pre-tool hooks or EDR sensor.

spoor is: one static Go binary that turns every agent action on an endpoint into a normalized event within milliseconds, runs deterministic detection ON the endpoint (so content never has to leave it), cross-checks three independent telemetry surfaces to detect its own blind spots, and hands results to the two control planes ops teams already run: FleetDM/osquery (state, policy, deployment) and Fluent Bit (streaming to anywhere). No server of our own.

## 2. Components (single binary, multi-call)

```
spoor scan            one-shot discovery + posture -> stdout / state DB / events
spoor hook            hook entrypoint invoked by agents (stdin JSON) -> event (+ optional allow/deny/ask)
spoor run             daemon: hook socket, transcript tailers, process monitor, periodic scan, detection, sinks, heartbeat
spoor hooks install   write managed-tier hook config for each agent (Claude Code, Codex, Copilot CLI, Gemini CLI, Cursor)
spoor rules test|lint run inline rule tests / validate packs
spoor bench           replay scenario corpus, report precision/recall per technique
spoor export          print Fleet GitOps bundle / Fluent Bit config / K8s manifests for this install
spoor.ext             same binary invoked by osquery as an extension (detects --socket): tables + optional embedded daemon
```

Pipeline inside `run` and `hook`:
`source -> normalize -> enrich (features, process lineage, container, repo) -> detect (stateless + session state) -> redact (privacy tier) -> emit (sinks + state store)`

## 3. Telemetry sources (the "three surfaces")

1. Hooks (push, real time, pre-execution, self-reported by the agent). Installed in the MANAGED tier so users cannot disable them: Claude Code `managed-settings.d/50-spoor.json`; Codex `requirements.toml [hooks]` (or system `hooks.json`); Copilot `policy.d/spoor.json`; Gemini system `settings.json`; Cursor enterprise `hooks.json`. One wire contract covers Claude/Codex/Copilot (stdin JSON, exit 2 = block, `hookSpecificOutput.permissionDecision`), Gemini and Cursor need small dialects.
2. Transcripts (pull, complete, lagging by seconds, self-reported, needs zero agent configuration). Incremental tail with byte-offset checkpoints of Claude Code JSONL, Codex rollouts, Copilot `events.jsonl`, Gemini journals; Cursor SQLite later.
3. Process telemetry (independent of the agent, lossy for short-lived processes). Polling process snapshots (pure Go) to find running agents, their argv flags, env markers (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CODEX_SESSION_ID`, `GEMINI_CLI`), config-dir overrides (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`...), and long-lived children. Short-lived exec ground truth is delegated to osquery evented tables via SQL joins against a `spoor_agent_processes` table (no kernel sensor of our own).

Coverage correlator: per (agent process, session) record which surfaces were seen. Emit detections when they disagree: transcript shows tool calls hooks never reported (hook bypass), agent process with neither hooks nor transcript (blind agent: `--bare`, `--no-session-persistence`, relocated config dir), managed hook file missing/modified (drift), transcript truncated or inode changed mid-session.

## 4. Event model

One compact JSON object per line. Envelope: `v, id (UUIDv7), ts (RFC 3339 UTC, always fractional), seq, kind (activity|inventory|posture|detection|health), type, source (hook|transcript|process|scan), host{id,name,os,arch}, user{name,id}, agent{id,name,version,pid,surface}, session{id,parent_id,cwd,permission_mode,model}, tool{name,kind,use_id,mcp_server,mcp_tool,status,duration_ms}, target{command,path,url,host,query}, container{...}, repo{...}, detection{...}, inventory{...}, privacy`.
Activity types: `session.start|end, prompt.submit, tool.pre, tool.post, subagent.start|stop, turn.end, permission.decision, config.change, agent.process.start|stop`.
Tool kinds (normalized across agents): `shell, file_read, file_write, file_edit, web_fetch, web_search, mcp, subagent, other`.
Formatters: native (default), OCSF (`--format ocsf`), OTLP logs JSON. Streams (file name prefix and Fluent Bit tag): `activity, detection, inventory, posture, health`.

## 5. Detection

Deterministic, local, streaming. Three layers:
1. Feature extraction in code (unit-tested): shell canonicalizer (tokenize pipelines, `&&`, subshells, `bash -c`, env-prefix, quotes; outputs commands[], downloads, pipes-to-interpreter, decoded base64 payloads, redirect targets, URLs/hosts); path classifier (secret, ssh, cloud credentials, agent config, sensor files, shell profile, vcs hook, CI config, browser data); host classifier (paste site, tunnel, webhook, raw IP, cloud metadata, LLM API); content scanners (secrets regex + entropy, hidden Unicode tag/bidi/zero-width, injection markers).
2. Declarative YAML rules over events + features: field predicates with modifiers (`contains, startswith, endswith, re, in, cidr, gt/lt`), `all/any/not`, severity, confidence, ATT&CK / ATLAS / OWASP tags, false-positive notes, inline test cases (`spoor rules test`).
3. Session state: rules can set flags with TTL (`untrusted_input`, `secret_read`, `egress`) and require flags, giving sequence detections such as the lethal trifecta (untrusted content read, then secret read, then network egress), plus thresholds and ordered sequences.

Posture rules run over inventory records (unpinned MCP launchers, plaintext secrets in MCP env, bypass/YOLO defaults, sandbox off, hooks disabled, API base URL override, managed policy missing).

Optional guard mode (off by default): the same engine answers PreToolUse hooks with deny/ask for rules marked `response: block|ask`. Fail-open by default; fail-closed is opt-in per agent where the agent supports it.

An LLM tier is NOT required and not on the endpoint. The deterministic tier is positioned as tier 0/1; sessions that match "suspicious but not conclusive" rules are tagged `escalate: true` so a downstream LLM judge (any provider) only sees a small fraction.

## 6. Outputs and integrations

Fluent Bit:
- Default: append-only NDJSON segment files `<dir>/<stream>-<seq>.ndjson`, never renamed or truncated, pruned by age/size; Fluent Bit `tail` with `db` (at-least-once, survives either side restarting, identical on Linux/macOS/Windows).
- Optional: built-in Fluent Forward v1 client (PackedForward + `chunk` ack, unix socket or TCP + `shared_key`), and OTLP/HTTP JSON logs exporter (works with any OTel collector, no Fluent Bit needed).
- Ship tested Fluent Bit YAML: tail parser, tag-by-stream routing (detections to SIEM, activity to object storage), examples for Splunk, Elastic/OpenSearch, Sentinel, Chronicle, S3, Kafka, Loki, OTLP.

FleetDM / osquery:
- Tier 0 (no binary): GitOps bundle over Fleet's built-in `ai_tools` etc.
- Tier 1 (binary, no extension): spoor maintains a small SQLite state DB; osquery exposes it through `auto_table_construction` (verified working through Fleet 4.94.1 live query). Tables: `spoor_agents, spoor_mcp_servers, spoor_extensions (skills/plugins/hooks/rules files), spoor_posture, spoor_detections, spoor_sessions, spoor_agent_processes, spoor_health`.
- Tier 2 (extension): the same binary as `spoor.ext` (osquery-go, verified loading CGO-free) with typed columns and constraint pushdown, reading the same state DB; optionally hosts the daemon loops itself so osquery/orbit supervises it (no service unit).
- Bundle: labels, policies (sensor healthy, hooks intact, no bypass mode, no unpinned MCP, no critical detections in 24h), packed reports, install scripts for Fleet Free (scripts) and package YAML for Premium, SQL that joins `spoor_agent_processes` with `process_events` / `es_process_events` / `process_etw_events`.
- Host identity equals osquery `system_info.uuid` so events join to Fleet hosts.

Containers / Kubernetes: `spoor run --host-root /host` as a DaemonSet with hostPID: discovers agents inside containers via `/proc/<pid>/root`, attributes pid -> container/pod via cgroup paths, writes NDJSON to a hostPath Fluent Bit already tails (or stdout). In-container mode: hook + stdout sink.

## 7. Deployment modes

| Mode | Needs | Gives |
|---|---|---|
| scan-only + ATC | binary on a timer (or Fleet script) | inventory + posture in Fleet |
| daemonless hooks | binary + managed hook config + Fluent Bit tail on the spool | real-time activity + detections, no service |
| daemon (service or osquery-hosted) | service unit or extension autoload | all three surfaces, coverage/tamper detection, heartbeat |
| DaemonSet | privileged-ish pod | containers and nodes |

Hook IPC: hook tries the daemon unix socket (root-owned daemon, SO_PEERCRED to record uid/pid and verify the caller's parent is a known agent). If no daemon, the hook evaluates rules in-process against a per-session state file and appends to a per-user spool file. Measured in this sandbox: a Go binary with sqlite+yaml+osquery-go linked starts, parses a hook payload and appends a line in p50 2.9 ms / p99 4.7 ms (slim binary 1.2 ms; `/bin/true` 0.9 ms).

## 8. Privacy

Tiers control what is EMITTED, not what detection sees locally: `metadata` (default: no prompt text, no tool output; commands and paths kept with secrets redacted; hashes + lengths for prompts), `redacted` (content with secret redaction and truncation flagged), `full`. Detections carry a redacted evidence snippet. No vendor cloud.

## 9. Integrity

Per-host monotonic `seq` and periodic `health` heartbeat with counters, so downstream can detect gaps. Root-owned event files in daemon mode. Self-protection rules: agent writes to its own hook/settings files, to spoor's files, or tries to stop the sensor / Fluent Bit / osquery.

## 10. Catalog, benchmark

Catalog: embedded YAML, >= 80 products with per-OS paths, Windows identifiers, bundle IDs, extension IDs, packages, process names, MCP config formats; user-extensible drop-in dir; reuse of uber/ADR catalog data under Apache-2.0 with attribution.
Benchmark: scenario YAML (event sequences -> expected detections), per-technique n >= 10 with benign look-alikes, runs with no API key in CI.

## 11. Load-bearing assumptions (attack these)

Telemetry
- A1. Managed-tier hooks exist and behave as documented for Claude Code, Codex, Copilot CLI, Gemini CLI and Cursor, and one handler binary can serve all five.
- A2. Hook overhead (process spawn per event) is negligible for users on all three OSes, including Windows with AV scanning.
- A3. Hooks fire for the events that matter (shell, file write, web fetch, MCP calls, prompts) in headless/SDK/CI modes too.
- A4. Transcript formats are stable enough to tail incrementally; breakage is detectable (schema drift health signal) rather than silent.
- A5. A user-space polling process monitor adds real value despite missing short-lived processes.
- A6. Cross-surface disagreement (hooks vs transcript vs process) is a reliable tamper/evasion signal with a tolerable false-positive rate.
- A7. Attribution of events to (user, agent, session) is correct on multi-user hosts and with subagents.

Detection
- A8. Deterministic rules + features catch a meaningful share of real-world agent abuse at high precision; an LLM is not needed for the first tier.
- A9. A shell canonicalizer makes command rules robust enough that trivial obfuscation does not bypass them, without a full shell parser.
- A10. Session-flag correlation (trifecta) will not drown analysts in false positives on normal developer workflows.
- A11. Running detection on the endpoint (attacker-influenced machine) is acceptable; rule logic being public does not defeat it.
- A12. Guard mode (blocking in the hook) is safe to offer: fail-open default, low latency, low enough false positives.
- A13. Inline rule tests + a scenario benchmark give honest quality numbers.

Integration
- A14. NDJSON segment files + Fluent Bit tail is the right default transport on all OSes and gives at-least-once delivery.
- A15. A hand-written Forward client and OTLP/HTTP JSON exporter are worth shipping in v1.
- A16. osquery ATC over a WAL SQLite file is robust under concurrent writes and at Fleet scale (query cost, locking, schema changes).
- A17. One binary can also be the osquery extension, and hosting the daemon inside the extension process is a good idea under the osquery watchdog.
- A18. Fleet Free users can deploy with scripts + ATC alone; Premium users get packages/policy automations.
- A19. Our tables add enough beyond Fleet's built-in `ai_tools` / `ai_agent_sessions` to justify existing on Fleet hosts.
- A20. Host identity can match osquery's `system_info.uuid` without osquery being present.

Scale and operations
- A21. Edge detection + stream routing keeps central cost flat: detections to SIEM, activity to cheap storage.
- A22. Event volume per developer is bounded and the sensor stays under 1% CPU / 50 MB RSS.
- A23. A SQLite state store with retention caps is sufficient; no central server is required.
- A24. One Go codebase gives real parity on Windows, macOS and Linux (paths, ACLs, services, process APIs) without CGO.
- A25. The DaemonSet model (hostPID + /proc/<pid>/root) sees agents in containers on real clusters (containerd, cgroup v2), and devcontainers/Codespaces/CI are coverable.

Security and privacy of the sensor itself
- A26. Metadata-only default still supports the detections we ship; privacy tiers are sufficient for works-council/GDPR-sensitive orgs.
- A27. The sensor does not become an attack surface: hook stdin is attacker-influenced, transcripts are attacker-influenced, config files are attacker-written, the socket is local-user reachable.
- A28. Spool/event files written in daemonless mode (user-writable) are an acceptable integrity trade-off because Fluent Bit ships within seconds.
- A29. Redaction (secret patterns + entropy) is good enough that shipping commands/paths in metadata mode does not leak credentials.

Product
- A30. "No server of our own" is a feature, not a gap (fleet-wide correlation, cross-host hunting, policy distribution, rule updates are covered by Fleet + SIEM).
- A31. A catalog of >= 80 products with Windows identifiers is achievable and maintainable; unknown agents are caught by heuristics.
- A32. Never executing discovered binaries and never starting MCP servers is the right trade-off even though it means no tool-description scanning.
- A33. Rule and catalog updates can ship independently of the binary (signed packs via Fleet files/scripts) safely.
- A34. Apache-2.0 reuse of uber/ADR catalog data and compatibility with its skill folder hash is legally clean and useful.

## 12. Competitive update from research (read `research/small-oss.md` sections 2-8)

The open-source bar is higher than the original brief assumed. As of 2026-11:
- perplexityai/numbat (Apache-2.0, CGO-free Go binary, 28 agents, managed hook install, OTLP collect, artifact `scan`, CEL + ordered sequence rules over shell-aware fields from mvdan.cc/sh, opt-in enforce). No daemon, no posture inventory, no packages, no SIEM mappings, no process signal, no osquery/Fluent Bit content.
- asymptote-labs/agent-beacon (MIT, Go, 29 runtimes, hooks + plugins + bundled OTel collector + polling, signed pkg/deb/rpm, MSI, CEL rules with correlation evaluated by batch `scan`; Fleet rollout and blocking are Enterprise-only, SaaS console).
- Agentmetry (Python, hooks + MCP stdio proxy, 14 sequence rules, hash-chained trail, SIEM sinks, heartbeat with hooked/unhooked state).
- Fleet fleetd ships `ai_tools` (inventory + risk flags), `mcp_listening_servers`, and unreleased `ai_agent_sessions` / `ai_agent_session_messages` (transcript parsers for 5 agents).
- falcosecurity/prempti (hook -> Falco plugin), gendigitalinc/sage (300+ heuristics, cloud lookups), eunomia-bpf/agentsight (Linux eBPF, no rules).
- uber/ADR already ships sensor JSON through Fluent Bit in production, so "uses Fluent Bit" alone is not new.

What nobody ships (verified by the research agents): osquery tables for findings / sensor health / hook coverage plus Fleet GitOps content; a tested first-class Fluent Bit path (segment contract, forward client, shipped configs, CI against the real image); OS process corroboration of hook/transcript telemetry with cross-surface tamper detection; any Kubernetes story; a streaming on-endpoint detection daemon with multi-surface correlation; an open benchmark corpus beyond ~57 cases.

Additional assumptions
- A35. Sigma-style YAML predicates over code-computed features (shell AST via mvdan.cc/sh, path/host classes) are a better rule format for this audience than CEL (the choice of Beacon and numbat), and convert to Sigma for SIEM-side use.
- A36. Building our own hook/transcript layer is justified versus consuming numbat or Beacon output as an input and focusing only on Fleet/Fluent Bit/correlation; covering 5 major agents well beats 28 agents shallowly.
- A37. Our differentiators (Fleet-native tables and bundle, Fluent Bit-native transports, three-surface corroboration, containers, edge streaming detection, privacy tiers, benchmark) are what the target user (a Fleet + Fluent Bit shop) actually values, and are defensible if numbat or Beacon add them.
