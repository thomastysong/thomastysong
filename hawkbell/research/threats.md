# Threat corpus for coding/desktop AI agents, 2025 to Nov 2026, as detectable behaviour

## Executive summary (5 lines)
1. The dominant in-the-wild class of 2026 is not prompt injection but **supply-chain worms that plant agent/IDE auto-run config** (`.claude/settings.json` SessionStart hook, `.gemini/settings.json`, `.cursor/rules/*.mdc`, `.vscode/tasks.json` folderOpen): Mini Shai-Hulud (May), Miasma (Jun), ChainDrop (Aug), Tensorlake (Oct). These never pass through a tool-call hook, so a hook-only sensor is blind to them; process lineage plus config-file integrity is mandatory.
2. The second class is **"repo/config is code"**: 40+ CVEs (67 records read) where opening a folder or an agent file-write reaches execution (pre-trust hooks, `ANTHROPIC_BASE_URL`, `.git/config core.fsmonitor`, MCP config auto-load, symlinks, plugin pin swaps, deeplinks). All are checkable as posture (file state + version) with near-zero false positives.
3. The third class is **agent-mediated exfiltration/destruction** (lethal trifecta, DNS/markdown-image/allowlisted-domain channels, `terraform destroy`, `volumeDelete`). Single events are ambiguous; session-scoped taint sequences are what separate attack from work.
4. uber/ADR's runtime detector is two LLM tiers with one deterministic check (Unicode tag/bidi regex); its taxonomy (ADR.T0001 to T0017) and 304-task benchmark model enterprise MCP business workflows, not the endpoint incidents below. Snyk agent-scan's codes cover static MCP/skill content; its runtime guard forwards hooks to api.snyk.io. Neither ships open deterministic runtime rules.
5. Recommendation: about 50 deterministic rules (below) over four signal planes (hook, process, file/config, inventory), 12 stateful sequences, an updatable IOC/version feed, and an LLM judge reserved for natural-language content (instruction files, skills, tool descriptions, intent alignment).

## 4. Sequence/correlation detections (state required)
State key: `session_id` plus `agent_id` subtree; taint bits with provenance, kept across compaction; a second store keyed by file hash for cross-session rules.
- **S1 Lethal trifecta**: untrusted ingest (WebFetch/WebSearch result, MCP result from a server tagged untrusted, Read under `node_modules|vendor|Downloads`, `gh issue|pr view`) then R21/R42 then R23-R30, with no intervening user prompt naming the destination. C.
- **S2 Write-to-execution**: untrusted ingest then R11/R13 then a new process whose command equals the written config value. C.
- **S3 Install-time worm chain**: lifecycle script then any two of (runtime download to temp, AI CLI spawn, AI credential read, control-file write) then `gh`/GitHub API/`npm publish`. C.
- **S4 Open-and-run**: first sighting of a repo hook/task hash on this host plus R06 within seconds of open. H.
- **S5 Approved-then-swapped**: MCP or plugin entry approved at hash A, launched at hash B with no approval event between (MCPoison, Plugin4Shell). C.
- **S6 Tool-definition rug pull**: tool-list hash changes mid-session (for example after call 3), followed by R21. H.
- **S7 Deny-then-evade**: PermissionDenied or guard block on binary X, then within N calls X reached through R34/R35, then R36. H; this is the Ona pattern and needs no attacker.
- **S8 Collect, stage, exfil**: at least N distinct SECRET_PATHS in M minutes, then archive/encode, then egress. C.
- **S9 Destructive burst**: at least N R40/R41 events in M seconds, or iteration over cloud profiles. C.
- **S10 Memory persistence**: untrusted ingest then write to memory/instruction file; in a later session `InstructionsLoaded` of that hash followed by egress or install. H.
- **S11 Cross-repo propagation**: agent or lifecycle process writes control files in repos other than cwd, then commits/pushes to many branches. C.
- **S12 Endpoint override then credentialed traffic**: R07 followed by model traffic to the new host. C.

## 5. Posture checks versus runtime detections
- **Posture (osquery-friendly, scheduled, diffable)**: R02 counts, R05, R07-R10, R14-R18, R50-R53, inventory of agents/MCP/skills/plugins/extensions with hashes, CI workflow audit (`pull_request_target|issues|issue_comment` + AI action + secrets + Bash allowed), managed-settings presence (`allowManagedHooksOnly`), trust-dialog and sandbox settings.
- **Runtime, hook plane**: R11-R13, R21, R23-R48 (tool intent and arguments).
- **Runtime, OS plane (no agent cooperation)**: R01, R03, R04, R06, R20, R22, R39, R45, R46, R49, R54. This plane is the only one that sees worms, infostealers, hooks, GitSpawn and in-process mods.

## 6. Benign behaviour that must not alert alone
Reading `.env` to fix a config bug; `cat ~/.aws/config` (not `credentials`); `aws sts get-caller-identity`; `curl -d @payload.json http://localhost`; `rm -rf node_modules dist build .next target` inside the workspace; `git push --force-with-lease` on a feature branch; `--no-verify` on WIP commits; agents updating `CLAUDE.md`/memory after `/init`; a user asking the agent to add an MCP server; `npx -y` MCP servers (the ecosystem default); `find . -exec`/`sed -i` refactors; `terraform destroy` in a sandbox workspace; `ngrok` for webhook testing; `kubectl get secret` for one named secret; security engineers running nmap; headless bypass-mode agents in CI containers and devcontainers; orchestrators spawning child agents; official installers (`claude.ai/install.sh`, rustup, brew); emoji/RTL Unicode; shields.io badges; git-lfs filters and `.husky` hooks; loopback model endpoints.

## 7. Where an LLM judge is and is not needed
- **Not needed (deterministic)**: every posture rule, lineage rules, path/flag/regex rules, hash drift, version feed, hidden-Unicode detection, and all sequences given good taint sources.
- **Needed**: (a) whether instruction/skill/tool-description text is manipulative (R17 confirmation, E001/E004 equivalents, split-fragment attacks such as GhostSplice); (b) user-intent alignment for ambiguous single events (did the user ask for this deletion, this MCP server, this upload?); (c) memory writes that are semantically poisoned but syntactically clean; (d) encoded/encrypted instruction content; (e) triage summarisation. Run it only on rule or sequence hits, off the blocking path, with tool output treated as data. An LLM approval classifier is not a control: Auto Mode was defeated in 60 to 80% of runs [S].

## 8. Gaps and caveats
- Sep-Nov 2026 items rely on secondary compilations; dates and counts differ between vendors (ChainDrop 353 to 1,684 versions).
- Bypass flags for Codex, Copilot CLI and cursor-agent are from memory; confirm against current CLIs before shipping R01/R02.
- File-read telemetry (R22) is not available from stock osquery `file_events`; it needs EndpointSecurity, eBPF/fanotify or ETW.
- Tool-definition drift (S6) needs MCP traffic capture or a proxy; a periodic probe misses per-client counters.
- The report runs past the nominal 2,500 words because the brief also requires 40+ rules and a per-incident signal table.
