# Long-tail agent surfaces: what a discovery catalog must fingerprint (2026-11-11)

**Executive summary**
1. uber/ADR `catalog.json` (v2026.10.12, 37 entries) and snyk/agent-scan (14 clients), agent-bom (29) and agentshield (10) are all path/name tables with no rename history, no lifecycle state and (ADR) zero Windows identifiers; ADR's catalog lacks 60+ of the products listed below.
2. June to November 2026 broke many fingerprints: Windsurf is now `Devin.app` (same bundle id), Gemini CLI consumers moved to Antigravity CLI `agy`, ChatGPT.app now ships as bundle id `com.openai.codex` and Atlas is discontinued, Roo Code shut down (fork: Zoo Code), llama.cpp's default port moved 8080 to 9931, goose left Block for AAIF, opencode has a v2 package.
3. Several incumbent fingerprints are wrong today against primary sources (ADR: Copilot CLI binary, Amp npm name, Jan and Perplexity bundle ids, `brew:claude`; agent-bom: Roo MCP filename, Windsurf path, Continue `config.json`).
4. Homebrew cask/formula files, npm and PyPI metadata are machine-readable primary sources for bundle ids, zap paths and binary names: a catalog can be regenerated from them in CI instead of hand-edited.
5. Name-only matching is unsafe: `goose`, `amp`, `q`, `gemini`, `agent`, `server` and npm/PyPI squats (`kiro-cli`, `antigravity-cli`, `openhands`, `nanoclaw`) all collide; identity needs two independent evidence classes.

**Marking convention.** Every cell is VERIFIED (read this session from a primary source listed in Sources) unless it ends in `?`, which means UNVERIFIED (memory, search snippet, or copied from an incumbent's table). `AS` = `~/Library/Application Support`; `GS` = VS Code `User/globalStorage`.

## 3. Heuristics for unknown agents

1. **Config shape, not path.** Parse any small JSON/JSONC/TOML/YAML under home and repo roots and classify by key: `mcpServers` (Claude, Cursor, Gemini, Qwen, Factory, Kiro, LM Studio, llama.cpp), `mcp` (opencode, Kilo, Crush), `context_servers` (Zed), `amp.mcpServers`, `servers` (VS Code `mcp.json`), TOML `mcp_servers` (Codex), YAML `extensions` (goose), YAML `mcp_servers` (Hermes), YAML `mcpServers` list (Continue). Accept a value object with `command`+`args` or `url`+`headers`.
2. **Shared convention directories.** `~/.agents/skills`, `~/.config/agents/skills`, `<repo>/.agents/`, `AGENTS.md`, `SKILL.md` folders: read by Crush and OpenClaw (and Amp, per snyk's table), so they reveal an agent even when the product is unknown.
3. **ACP registrations.** Zed `agent_servers`, JetBrains ACP registry, argv containing `acp` or `--acp`, binaries named `*-acp`.
4. **Network.** Process with established TLS to model hosts (ADR's list plus `api.githubcopilot.com`?, `chatgpt.com`?, `cloudcode-pa.googleapis.com`?, `api.moonshot.ai`?, `dashscope.aliyuncs.com`?, `portal.nousresearch.com`). Prefer updater/download hosts from section 1 for identity: they are product specific, API hosts are shared by dozens of clients.
5. **Listening sockets.** Probe loopback listeners owned by non-system processes with `GET /v1/models`, `/api/tags` (Ollama), `/health` + `/props` (llama.cpp), `/api/v1/models`; classify by response shape, not by port.
6. **Process shape.** Flags `--dangerously-skip-permissions`, `--yolo`, `--auto-approve`, `--output-format stream-json`, `mcp`, `serve`; children `npx -y @modelcontextprotocol/*`, `uvx mcp-*`; env names `*_API_KEY`, `OTEL_EXPORTER_OTLP_*`, `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL`.
7. **Binary strings.** Embedded `api.anthropic.com/v1/messages`, `anthropic-version`, `/v1/chat/completions`, `modelcontextprotocol`, `tools/call`, `agentclientprotocol` in unsigned or user-writable executables.
8. **Dependency evidence.** SDK names from 1d in lockfiles, `dist-info`, `node_modules`, and image layers.
9. **Model files.** `.gguf`, `.safetensors`, `sha256-*` blobs over ~100 MB, `.mlmodelc`, `.onnx` with `tokenizer.json` beside them; HF cache `models--*` directories.
10. **Persistence.** LaunchAgents, systemd user units, Scheduled Tasks whose program is a known agent binary or contains `gateway`, `agent`, `mcp`.

## 4. False-positive traps

- **Name collisions:** brew `goose` is a Go DB migration tool; brew `amp` is a text editor; brew `q` is a DNS client; brew `forge` is unrelated to `forgecode`; brew `nanobot` (obot MCP builder) differs from PyPI `nanobot-ai`; PyPI `exo` is a genomics tool; Grok Build installs a binary literally named `agent`.
- **Squats and stubs:** npm `kiro-cli` and `antigravity-cli` are placeholders exposing bin `kirox`; npm `openhands` is a security holding package; npm `picoclaw` and PyPI `nanoclaw` install an unrelated "cmdop" CLI; npm `hermes-agent` is unofficial.
- **Shared dot-directories:** MacPaw's Gemini duplicate finder (`com.macpaw.site.Gemini`) also owns `~/.gemini`. `~/.codex` now belongs to ChatGPT.app as well as the CLI. `~/.gemini` is shared by Gemini CLI, Antigravity hub, IDE and CLI.
- **Stale residue:** state directories survive uninstall and product death (Roo, Atlas, Windsurf, Amazon Q). Report "configured, not installed" separately and require a live binary, app registration or recent mtime for "present".
- **Ports:** 8080, 8000, 5000, 3000, 7860 and 4000 are generic dev ports (macOS AirPlay Receiver uses 5000?); never emit a runtime finding from a port alone.
- **Network:** `huggingface.co`, `storage.googleapis.com`, `*.amazonaws.com` and CDN-fronted addresses are shared with non-AI traffic; `api.openai.com` is called by ordinary SaaS desktop apps.
- **Bundled runtimes:** every Electron app ships `node`; VS Code forks ship a `bin/code` shim (Cursor and Kiro casks both do); JetBrains plugins live inside versioned IDE dirs.
- **Preinstalled assistants:** Microsoft 365 Copilot arrives with Office; Gemini in Chrome and Copilot in Edge are browser features, visible only through browser policy and profile prefs, not as installs.
- **Custom distributions:** goose documents rebrandable "custom distros"; opencode has forks (Kilo), Codex has forks (`coder`), Pi has forks (`omp`). Fingerprint the lineage (config shape, embedded strings), not the brand.
